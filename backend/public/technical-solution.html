Live Tracking Technical Solution

Overview

RUSC is designed for sailing schools that need live visibility of training boats while they are on the water. Each boat carries a compact device that reads GPS position, compass heading, battery level, and link status, then sends the data over Wi-Fi HaLow to a beach-side gateway. The gateway forwards the stream to the current cloud backend, where the website shows boat position and direction in real time.

End-to-End Architecture

Boat Device Placement

The device is intended to be attached with a stick at the back of the boat. This keeps the electronics higher above the water, improves the radio position, and gives the onboard camera a strategic view of the whole boat, including the athletes.

Why Wi-Fi HaLow

Wi-Fi HaLow is still Wi-Fi: it keeps the familiar IP networking model, security concepts, sockets, gateway routing, and backend integration patterns. That simplifies the technical solution compared with custom radio protocols because telemetry can travel as normal network data.

Range and Antenna Strategy

The HT-HC33/HaLow platform is designed for long-range links. With a directional Yagi antenna on the beach-side gateway, clear line of sight over water, correct alignment, and local regulatory limits, the school can target course-scale coverage in the 1-2 km class, with longer links possible in favorable conditions and lower data-rate settings.

Actual distance depends on antenna gain, mounting height, sea state, interference, allowed transmit power, country settings, and the selected HaLow channel width/data rate.

Fleet Capacity

Wi-Fi HaLow was created for dense IoT networks and the 802.11ah standard can address up to 8191 stations per access point. In practice, a sailing school fleet will be sized by airtime, update rate, payload size, antenna coverage, and gateway configuration. Current firmware is optimized for a small fleet first and can be tuned upward as the use case grows.

Network Roles and Data Flow

Wi-Fi Provisioning

The gateway includes Wi-Fi provisioning so the sailing school can configure its own local internet path. For example, an instructor can use a phone hotspot on the beach and let the gateway send live data to the cloud backend without changing firmware.

Current Cloud Backend

The current backend runs in the cloud. Device2 forwards decoded telemetry to the backend, and the website reads the latest positions through the REST API. This keeps the live tracking page reachable from normal browsers and makes future event and athlete workflows easier to add.

Future Evolutions

  1. The HiLetgo MPU9250 is also an accelerometer and gyroscope, so future telemetry can add tilt, yaw, and acceleration parameters for boat handling analysis.
  2. The HT-HC33 device also has a camera. Real-time video is not expected over the long-range link, but video can be stored onboard and later transferred via Wi-Fi so the instructor or coach can review the session with the athlete.
  3. Accessories can be added around the device, for example a wind sensor, taking advantage of the Bluetooth environment and accessory interfaces.
  4. Buoys can have their own dedicated devices, possibly including wind sensors, so the course itself becomes instrumented.
  5. The website will be ready to register athletes, boats, devices, and events, linking live telemetry to structured training and evaluation sessions.
